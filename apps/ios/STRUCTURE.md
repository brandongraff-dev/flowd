# apps/ios — structure guide for feature agents

One page. Read it, then read `docs/CONVENTIONS.md` section 5. There is **no Swift compiler on the Windows dev machines**: CI (`.github/workflows/ios.yml`, macOS runner) is the compiler of record, so write conservative Swift and re-read every file as the compiler would.

## Canonical facts

| | |
|---|---|
| Targets | `Flowd` (app, `app.flowd.creator`) · `FlowdWidgets` (WidgetKit + Live Activity, `app.flowd.creator.widgets`) · `FlowdTests` (unit, `app.flowd.creator.tests`) |
| Min OS / language | iOS 17.0, Swift 5 language mode, `@Observable` (Observation), `NavigationStack`, async/await, no packages |
| Isolation | Default isolation is **nonisolated** (we do not set default MainActor). Put `@MainActor` on every view model and on `AppState`. Models are `struct ... : Codable, Hashable, Identifiable, Sendable` |
| App group / URL scheme | `group.app.flowd.creator` / `flowd://` |
| Project file | Generated by XcodeGen from `project.yml`. Never hand-edit `Flowd.xcodeproj` (git-ignored), `Info.plist` or `*.entitlements` (generated mirrors of `project.yml`). If you need a new permission string, capability or build setting, make the smallest additive edit to `project.yml` and list it in your report |

## Where files go

```
Flowd/App/            FlowdApp, AppState, RootView, Router, TabShell            (app-shell work only)
Flowd/DesignSystem/   Tokens.swift (generated) · Theme · Typography · Motion · Haptics · Glass/ · Components/ · Charts/
Flowd/Core/           Models/ (mirror packages/contract/DOMAIN.md) · Services/ (FlowdAPI, MockFlowdAPI, LiveFlowdAPI)
                      Persistence/ (SwiftData drafts, caches) · Engine/ (pricing/scoring mirrors) · Utilities/
Flowd/Features/<Area>/  Onboarding Home Bounties Studio Wallet Profile Leaderboard Crews Tournaments Inbox
                        RateCard Earnings Academy Tools Settings          (one folder per area, already created)
Flowd/Resources/      Assets.xcassets · Fixtures/ (synced JSON, do not edit) · Info.plist (generated)
FlowdWidgets/         widget bundle, widgets, Live Activity UI
Shared/               code compiled into BOTH the app and the widget (ActivityKit attributes, e.g. PostActivityAttributes.swift)
FlowdTests/           one test file per area, `@testable import Flowd`
```

- Drop a new `.swift` file into the right folder; XcodeGen picks it up by directory (`xcodegen generate` locally; CI always regenerates). No project edits needed.
- Delete the `.gitkeep` from a folder once it has real files (harmless if you forget).
- `Shared/` and `DesignSystem/Tokens.swift` are the only app code the widget extension sees. Anything in `Shared/` may use Foundation, SwiftUI, ActivityKit and `Tokens` — nothing from `Core`, `Theme`, `Glass`, `Components`.
- Fixtures are a folder reference, bundled under `Fixtures/`. Load with a tolerant lookup: `Bundle.main.url(forResource: name, withExtension: "json", subdirectory: "Fixtures") ?? Bundle.main.url(forResource: name, withExtension: "json")`. Decode with `.convertFromSnakeCase` and `.iso8601`.

## Naming

- File = primary type (`BountyCardView.swift`). Screens `XView`, state `XViewModel`, models singular nouns that match DOMAIN.md (`Bounty`, `Submission`, `Payout`). Money is `Int` cents (`amountCents`); format at the edge only.
- Test names say behaviour: `testPendingMovesToClearedAfterSettlement`.
- Never declare a type named `Flowd` (it is the module name). Terminology is fixed: bounty, creator, payout, Wallet, Studio, Hook Score, Flow Score, Flo, Daily Drop, Crews, Tournaments.

## DesignSystem rules

1. Colours, fonts, spacing, radii, motion come from `Theme` / `Typography` / `Motion` (built on `Tokens`). No hex, no `Color(red:)`, no `.font(.system(size:))` in `Features/**`.
2. Glass only through `.flowdGlass(...)`, `FlowdGlassContainer`, `FlowdGlassButtonStyle`. `#available(iOS 26, *)` appears **only** inside `DesignSystem/Glass`.
3. Max two glass layers deep. Content on glass must hold AA contrast; add a scrim, not less blur.
4. Money and counts are large, tabular, animated, mint when positive; pending vs cleared always distinct.
5. Reduce-transparency, reduce-motion, Dynamic Type and VoiceOver labels are handled in wrappers or by you, never skipped.
6. Icons are SF Symbols. No remote images; imagery is generated (gradients, shapes, SwiftUI drawing).

## Add a feature (checklist)

1. Models in `Core/Models` (if new) and an API method on `FlowdAPI` + `MockFlowdAPI` (+ `LiveFlowdAPI` stub that compiles).
2. `Features/<Area>/XViewModel.swift`: `@MainActor @Observable final class`, takes the API by protocol, exposes loading / loaded / empty / failed states.
3. `Features/<Area>/XView.swift`: small subviews, at most ~10 siblings per builder (use `Group`), designed empty / loading / error states, VoiceOver labels.
4. End **every** view file with a `#Preview` that uses `MockFlowdAPI` and fixture data (add a second for a dark / empty state when it matters).
5. Navigation goes through `Router` (typed destinations on `NavigationStack`). Add a test in `FlowdTests` for the view model or engine logic.
6. Re-read your files: imports, labels, optionals, exhaustive `switch`, `Identifiable`, `@State` / `@Binding`, `@MainActor` boundaries.

## Forbidden

`try!`, `!` force unwraps, `fatalError` in shipped paths, `print` (use `Logger`), `AnyView`, `DispatchQueue.main.async` (use `@MainActor`), `ObservableObject`/`@Published`/`@StateObject` (use Observation), `UIKit` unless wrapping `AVFoundation`-style needs, third-party packages, hard-coded URLs or secrets, `UIDesignRequiresCompatibility` in plist (it opts out of Liquid Glass), editing synced or generated files, touching another area's folder, TODO / placeholder text or dead buttons in shipped UI.
