# flowd for iOS

The native SwiftUI creator app: onboarding, bounty feed, Studio (camera, teleprompter, Hook coach), Wallet, rate card, Crews, Tournaments, plus a Live Activity and Home Screen widget. Liquid Glass on iOS 26, `Material` fallback on iOS 17-25.

| | |
|---|---|
| Xcode project | generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (no hand-written `.xcodeproj`) |
| Targets | `Flowd` app (`app.flowd.creator`) · `FlowdWidgets` widget + Live Activity extension (`app.flowd.creator.widgets`) · `FlowdTests` unit tests (`app.flowd.creator.tests`) |
| Deployment | iOS 17.0+, iPhone only, portrait, Swift 5 language mode, no third-party packages |
| App group | `group.app.flowd.creator` (app and widget share cached wallet data) |
| URL scheme | `flowd://` |
| Capabilities | Sign in with Apple, App Groups, Push Notifications (`aps-environment: development`), Live Activities (plist keys, no capability) |

## Prerequisites

- A Mac with **Xcode 26** (needs macOS Sequoia 15.6 or later; macOS 26 recommended for the iOS 26 simulator runtime).
- XcodeGen: `brew install xcodegen` (latest release at the time of writing: 2.46.0, 2026-07-16).
- Node 22+ for the sync script (`node -v`).
- For devices and TestFlight only: a paid Apple Developer Program team (see Signing).

Windows is fine for editing, but nothing here builds without a Mac. CI on a macOS runner compiles every push (see CI).

## Quick start

```bash
npm run sync                                   # repo root: tokens + fixtures -> the app
cd apps/ios
xcodegen generate                              # writes Flowd.xcodeproj, Info.plists, entitlements
open Flowd.xcodeproj                           # scheme "Flowd", any iPhone simulator, Cmd+R
```

Re-run `xcodegen generate` whenever you add, remove or rename files, or edit `project.yml`. Re-run `npm run sync` after a change in `packages/tokens` or `packages/contract/fixtures`. A fresh clone needs both steps, because `Flowd.xcodeproj` is git-ignored.

## Sync: where tokens and fixtures come from

The repo root owns the canonical design tokens and demo data. Never hand-edit the synced copies in the app.

| Source | Synced to | Notes |
|---|---|---|
| `packages/tokens/dist/Tokens.swift` | `Flowd/DesignSystem/Tokens.swift` | compiled into the app **and** the widget. The committed file is a minimal placeholder so the project builds before the first sync |
| `packages/contract/fixtures/*.json` | `Flowd/Resources/Fixtures/` | bundled as a folder reference named `Fixtures`; the mock API decodes them (snake_case keys, ISO-8601 dates). New files are bundled without re-running `xcodegen` |

`npm run sync` is `node scripts/sync.mjs` at the repo root.

## Run in the simulator

1. `open Flowd.xcodeproj`, pick the **Flowd** scheme and an iPhone simulator (iPhone 17 ships on the GitHub macOS 26 runner image), press Cmd+R.
2. Widget: run the app once, long-press the Home Screen, add the "flowd" Earnings widget.
3. Tests: Cmd+U, or from the shell:

   ```bash
   xcodebuild test -project Flowd.xcodeproj -scheme Flowd \
     -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO
   ```

   Pick any installed iPhone name from `xcrun simctl list devices available`.
4. The simulator has no camera, so test Studio capture on a device; importing from the photo library works in the simulator.
5. The app runs fully offline against `MockFlowdAPI` (bundled fixtures, in-memory mutations).

## Signing

- **Simulator and CI need no signing.** CI builds with `CODE_SIGNING_ALLOWED=NO`.
- **A real device or TestFlight needs a paid Apple Developer Program team.** The entitlements (Sign in with Apple, Push Notifications) cannot be provisioned by free personal teams.
- Put your 10-character Team ID in `project.yml` under `settingGroups.flowd_common` as `DEVELOPMENT_TEAM: ABCDE12345` (a commented hint is there), then `xcodegen generate`. Setting the team in Xcode's UI alone is lost on the next regenerate.
- Signing style is Automatic. The first device build with `-allowProvisioningUpdates` (or Xcode's UI) creates the App IDs `app.flowd.creator` and `app.flowd.creator.widgets`, registers the app group `group.app.flowd.creator` and enables Sign in with Apple and Push Notifications on the app ID.
- `aps-environment` is `development` in the spec; Xcode swaps in the production value from the distribution provisioning profile when you archive for the App Store.

## CI

- `.github/workflows/ios.yml` (macOS 26 runner): latest stable Xcode, `brew install xcodegen`, `node scripts/sync.mjs`, `xcodegen generate`, `xcodebuild build` for `generic/platform=iOS Simulator`, then `xcodebuild test` on the newest installed iPhone simulator (it falls back to `name=iPhone 17`). Logs and the `.xcresult` upload as an artifact.
- `.github/workflows/web.yml`: Node 24, `npm ci`, typecheck, lint, test and build for `apps/web`.

## TestFlight

1. Join the Apple Developer Program and create the app record in App Store Connect with bundle id `app.flowd.creator`.
2. Set `DEVELOPMENT_TEAM` (above). Bump `CURRENT_PROJECT_VERSION` in `project.yml` for every upload; `MARKETING_VERSION` is the user-facing version. The widget reads the same two settings, so app and extension versions always match.
3. Archive the `Flowd` scheme (Release, "Any iOS Device") and upload via Xcode Organizer, or script `xcodebuild archive` then `xcodebuild -exportArchive` with an `ExportOptions.plist` and an App Store Connect API key.
4. Apple requires uploads built with Xcode 26 or later (iOS 26 SDK) since 2026-04-28 (as reported by [Expo](https://expo.dev/blog/app-store-connect-minimum-sdk-26), quoting Apple's notice). Check Apple's current notice before the first upload.
5. TestFlight: up to 100 internal testers (App Store Connect users) with no review; external testers need the first build of each version to pass Beta App Review. Builds expire after 90 days.
6. `ITSAppUsesNonExemptEncryption` is `false` (the app uses only standard HTTPS). Revisit if custom cryptography is added.
7. Before the first App Store review (not needed for internal TestFlight): add `PrivacyInfo.xcprivacy` and complete the App Privacy answers to match what the app really collects, provide in-app account deletion, and replace the placeholder icon with the brand icon.
8. `UIDesignRequiresCompatibility` is deliberately **not** set: it opts out of Liquid Glass, and Apple has said it is ignored when building with the iOS 27 SDK ([Apple forum thread](https://developer.apple.com/forums/thread/832543)).

## Troubleshooting

- "No such file Flowd.xcodeproj": run `xcodegen generate` in `apps/ios`.
- New file not in the project / "cannot find X in scope": run `xcodegen generate` again, then check the file is inside `Flowd/`, `FlowdWidgets/`, `Shared/` or `FlowdTests/`.
- Xcode offers "Update to recommended settings": cosmetic; regenerate rather than accept, so `project.yml` stays the source of truth.
- Fixtures missing at runtime: confirm `npm run sync` ran, and that you load from the `Fixtures` subdirectory (see `STRUCTURE.md`).
- Widget not updating in the simulator: remove and re-add it, or relaunch the app; timelines are cached.
